# P1-C.1 — результат hardening

Статус: автономные проверки пройдены; подготовлена экспериментальная Windows x64 сборка. Доступа к установленной игре и паре игровых клиентов в этой среде нет: `TEST-A=NOT_RUN`, `TEST-B=NOT_RUN`.

## Изменения

- Логи классифицируются строго по опубликованным именам `goh_coop_checkpoint_call_to_arms.exe.log` (game process) и `goh_coop_checkpoint_call_to_arms_server.exe.log` (локальный server process). Автоматический выбор «последнего изменённого» файла удалён из подготовки и наблюдения.
- Каждое значение метаданных содержит источник и process role. HOST/CLIENT остаётся явным выбором оператора: имя executable сообщает тип процесса, но не сетевую роль игрока.
- Для подготовки marker обязательны manifest запись ожидаемого владельца и роли, корректные положительные size и SHA-256, совпадение выбранного и профильного архивов. Проверки не обходятся при отсутствующей записи.
- Client и server marker готовятся как отдельные операции из соответствующих process log. Каталог marker привязан к родителю точного лога, а не к TEMP менеджера. Оператор подтверждает неизменность TEMP/TMP процесса; это ограничение следует из использования `GetTempPathW` в процессе создания marker.
- Групповая сверка требует ручной protocol JSON с источниками и hashes всех клиентских логов плюс отдельного host server log. Локальные номера checkpoint сохраняются отдельно и никогда не считаются общим ID. Результат помечается только `OPERATOR_PROTOCOL_RECORDED_NOT_SYNCHRONIZATION_PROOF`.
- GUI показывает source log, выбранный архив, marker destination и результат локального preflight. Подтверждение является последним шагом; отмена не создаёт marker.

## Проверки

`python -m compileall -q tools` и `python -m unittest discover -s tools/tests -v`: 74 теста, все пройдены. Набор включает неверную роль лога, отсутствующую manifest запись, неправильный SHA-256, mismatch профиля, отсутствующий host server архив, неполные метаданные, повторную подготовку и безопасную отмену. Это синтетические тесты, не тесты игры.

Сборка и упаковка Windows выполняются workflow `.github/workflows/windows-v0.2.1.yml`. Ожидаемый артефакт: `GOH-Coop-Recovery-V0.2.1-FieldTest-win64.zip`.

## Ограничения

Имя лога указывает executable process. Каталог родительского лога соответствует каталогу, использованному `GetTempPathW` в момент записи лога. Публичный код не доказывает, что окружение процесса не меняется позднее; поэтому до marker требуется ручное подтверждение, что TEMP/TMP не изменились. Протокол участников — фиксированная операторская запись; независимого synchronization ACK в этих логах не установлено.

Игровые hooks, DLL injection, изменения сетевого протокола и обход игровых проверок не добавлялись. Не заявляется возможность восстановления живой сессии или успешной загрузки состояния всеми участниками.
