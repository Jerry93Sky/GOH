# Риски, лицензии и безопасные ограничения

## Лицензии изученных репозиториев

На дату анализа 2026-11-23 в двух клонах не обнаружены файлы `LICENSE`, `COPYING` или `NOTICE`; GitHub REST endpoint `/license` для обоих вернул 404. README `coa_script_extender` заявляет MIT, но endpoint и checkout не содержат проверяемого текста этой лицензии; перед заимствованием/распространением кода нужно получить и сверить лицензию у владельца. Для `nicko996/goh-coop-mods` явная лицензия в проверенных файлах не указана. Публичная доступность исходников сама по себе не является разрешением копировать и распространять их.

GOH P0 документы пересказывают архитектуру своими словами, цитируют короткие имена API/команд и содержат ссылки на источники. Файлы чужого кода не копировались. В `src/` нет third-party кода. Любой будущий код MinHook/GOHSE или их производные должны проходить отдельную проверку лицензии и атрибуции.

## Технические риски

- Сигнатуры, offsets, ABI и игровые структуры ломаются после обновлений; ложное единственное совпадение тоже опасно.
- Синхронная запись на simulation thread может вызвать зависание/desync; сохранение внутри script trigger может менять сериализацию.
- Engine save может не включать сетевой roster, random state, незавершённые script fibers, внешние игровые сервисы или клиентские значения.
- Разные профили, пути, права доступа, дисковое пространство и время записи могут дать неполный набор файлов.
- Текущая схема marker/повторного запуска зависит от живого процесса и in-memory mappings; авария или перезапуск меняют состояние.
- Игровые правила, аутентификация и защитные проверки не должны обходиться. Не проверялась совместимость с античитом/онлайн-сервисом.
- Архивные хеши и размеры не удостоверяют корректность/безопасность содержимого и не позволяют интерпретировать проприетарный формат.

## Ограничения на разработку

- Не менять исходные игровые ресурсы; любые будущие изменения — только в памяти и только после отдельного теста на изолированной копии, если вообще потребуется.
- Не помещать `version.dll` автоматически и не использовать стороннюю DLL-инъекцию в рабочую установку.
- Не отключать auth/anti-cheat/целостность.
- На неизвестной версии, неоднозначной/неполной сигнатуре, неожиданном прологе или недоказанном pointer layout — безусловный отказ от hook/patch.
- Отделять тестовую сборку, профиль и каталоги evidence от пользовательской игры.
- Не называть восстановление рабочим до повторяемого реального теста минимум на двух клиентах и локальном сервере.

P0 проект пока не выбирает лицензию для собственного кода и не включает игровой код.

## P1-B дополнение

V0.1 добавляет только независимо написанные Python модули и UI. Marker field names/values документированы по release tag `coop-checkpoint-v1.0.4` на commit `e7f13b3c2ab9d764a351afca4005ed034c918cca`; исходники и DLL автора не включены и не модифицированы. Для повторного распространения Coop Checkpoint разрешение не установлено; пользователь скачивает release отдельно. В собственный ZIP входят только GOH Recovery Manager, конфигурация и инструкции.

Windows file version, найденная под интерфейсом, не считается гарантированным game build. Mod folders могут существовать, но быть выключены. Marker writer использует ввод оператора для exact game-internal paths; даже правильный текстовый формат не подтверждает, что файл доступен целевому процессу/профилю или что scene load пройдёт. Импорт идемпотентен при точном совпадении checksum, блокирует иной файл и может продолжить синтетически прерванный import; это не подтверждает атомарность/надёжность диска или поведение при аварии ОС.
