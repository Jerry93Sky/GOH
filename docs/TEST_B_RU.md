# TEST-B: recovery между игровыми процессами

Сначала должен быть пройден TEST-A той же миссией и сборкой. На каждом ПК должны быть свои клиентский архив и локальный TEMP marker; host дополнительно использует свой серверный архив и server marker. Не считать один серверный архив заменой клиентских.

1. Создайте и проверьте checkpoint в TEST-A. Экспортируйте отдельные participant packages; host package должен содержать `coop_ckpt_srv.sav`.
2. Перенесите каждый ZIP вручную доверенным способом. Не включайте в архив credentials, Steam данные или весь пользовательский профиль.
3. Каждый игрок импортирует только свой пакет в локальную тестовую папку сохранений; host импортирует также server archive. Проверьте одинаковые checkpoint ID, internal mission path, build, mod fingerprint и roster.
4. Пока процессы старой сессии доступны, сохраните marker, если он был штатно создан авторским Reload. Для режима A запишите marker и точное время последней записи. Не обновляйте mtime, чтобы обойти 15-минутный срок.
5. Для режима B подготовьте для каждого процесса отдельный JSON с точным internal mission path, точным virtual `archive_path` из runtime лога Coop Checkpoint, собственным player ID, build, mission ID, mod fingerprint, ролью и исходным `player_mapping`. `archive_path` — archive base, обычно оканчивается `/`; это не локальное имя файла `.sav`. Host подтверждает `is_host: true`. Пустое или неизвестное значение — остановка.
6. После подтверждения готовности всех участников создайте локальный marker на каждом ПК. Успейте перейти в новый lobby и запустить ту же миссию до истечения 15 минут. Маркеры не пересылаются: путь архива обязан быть локальным на каждом ПК.
7. Не меняйте порядок/число игроков в первом прогоне. Запишите логи, marker наличие/TTL, точную миссию, owner mapping, objective, trigger и quant/game time. Наблюдайте не менее 10 минут.
8. Если архив/marker не найден, mission path не совпал, loader log показывает отказ или участник не прошёл загрузку, остановитесь и сохраните факт. Не подставляйте чужой клиентский архив.

Симулятор `parse_marker` проверяет только опубликованный текстовый формат и TTL; он не исполняет код игры. Результат теста `GAME_VERIFIED` не ставится автоматически.
