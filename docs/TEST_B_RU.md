# TEST-B: восстановление после завершения сессии

**Статус: `NOT_RUN`.** Протокол описывает будущий ручной полевой тест; автономные тесты и синтетический marker parser не заменяют игровой результат.

## Условия

- TEST-A пройден в выбранной миссии и на той же сборке игры.
- Доступны два реальных игровых клиента, отдельные тестовые профили, одинаковая миссия/mods и совместимый Coop Checkpoint.
- Сохранены резервные копии клиентских и host-server архивов.

## Процедура

1. В исходной сессии создайте checkpoint. Каждый участник сохраняет собственный `coop_ckpt.sav`; хост сохраняет дополнительно `coop_ckpt_srv.sav`.
2. Соберите с каждого компьютера собственные game process log и, на компьютере хоста, отдельный local server process log. Запишите пути, SHA-256, локальный checkpoint sequence и quant clock. Локальные `checkpoint #N` не являются общим ID.
3. Завершите старую игровую сессию, не меняя и не перезаписывая исходные архивы. Сформируйте peer ZIP каждого участника, проверьте manifest, размер и SHA-256.
4. Участники устно сверяют момент checkpoint и создают единый consistency protocol JSON со schema `goh-checkpoint-consistency-protocol-v1`, operator event label, `package_checkpoint_id`, mission/host IDs и отдельными источниками каждого client process плюс host server process. Не копируйте поля одного участника в запись другого. Этот протокол фиксирует согласованное наблюдение людей, а не sync ACK движка.
5. Создайте новое кооперативное лобби той же миссии и состава игроков. Убедитесь, что все участники готовы.
6. На каждом клиенте отдельно подготовьте client marker. На компьютере хоста подготовьте client и server marker отдельными операциями из соответствующих логов. Выберите фактический server process log: если он недоступен или его каталог не установлен, автоматическую подготовку не выполняйте.
7. Перед созданием marker проверьте role, источник metadata, архив, целевой путь marker и preflight. Подтвердите, что TEMP/TMP соответствующего процесса не изменился после записи лога.
8. Сразу загрузите ту же миссию. Сверьте на всех участниках mission/objective/trigger state, quant/game clock, подразделения и владельцев. Зафиксируйте video/screenshots и диагностические логи.

## Результат

Запишите `PASS`, `FAIL` или `INCONCLUSIVE` вместе с версией игры, списком модов, файловыми hashes и evidence. `PASS` не ставится только на основе одинаковых файлов или совпавших checkpoint sequence. См. [полевой guide V0.2.1](P1_C1_FIRST_RUN_RU.md) и [TEST-A](TEST_A_RU.md).
