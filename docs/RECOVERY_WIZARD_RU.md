# Порядок подготовки recovery

V0.2.1 — экспериментальный менеджер файлов. Preflight hardening описан в [P1-C.1 results](P1_C1_RESULTS.md). До реального игрового прогона сборка не может заявлять READY_FOR_FIELD_TEST.

1. **Миссия.** Сверьте internal mission path, наблюдённый в логе, между участниками. Роль и сетевой состав автоматически не предполагаются.
2. **Контрольная точка.** Выбирайте только комплект из полного participant checkpoint manifest либо ручных локальных снимков с внешним доказательством их общей точки. Локальный `checkpoint #N` не является общим ID.
3. **Участники.** Сверьте roster, game build, моды и роли. Не подставляйте отсутствующие runtime значения.
4. **Файлы.** Для каждого участника нужен его собственный `coop_ckpt.sav`; HOST дополнительно требует свой `coop_ckpt_srv.sav`. ZIP проверяется по size/SHA-256; чужой файл не заменяйте.
5. **Локальный plan.** Используйте отдельный participant ZIP, импортируйте без перезаписи. Не переносите Steam credentials и полный профиль.
6. **Готовность.** Каждый участник вручную подтверждает готовность в новом лобби. Это не сетевое подтверждение менеджера.
7. **Marker.** Обязательны отдельные точные логи game process и host server process, ручной protocol JSON для общей точки, точная запись manifest владельца/роли, size/SHA-256 и совпадение `ArchivePathResolver` с точным архивом выбранного профиля. Путь marker связан с родительской папкой соответствующего process log. Перед записью подтвердите, что TEMP/TMP процесса не изменились. Существующий marker не перезаписывается; TTL остаётся 15 минут. Одноразовый marker — не доказательство загрузки.
8. **Результат.** Запишите PASS, FAIL либо INCONCLUSIVE только по реальному игровому наблюдению и сохраните очищенные логи/параметры. Без запуска игры результат остаётся NOT_RUN.

Автоматического межкомпьютерного обмена или сетевого подтверждения каждого peer нет. Ручной consistency protocol фиксирует источники и операторское сопоставление, но не является synchronization proof.
