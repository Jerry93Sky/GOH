# Порядок подготовки recovery

V0.2 — экспериментальный менеджер файлов. До игрового прогона сборка не может заявлять READY_FOR_FIELD_TEST.

1. **Миссия.** Сверьте internal mission path, наблюдённый в логе, между участниками. Роль и сетевой состав автоматически не предполагаются.
2. **Контрольная точка.** Выбирайте только комплект из полного participant checkpoint manifest либо ручных локальных снимков с внешним доказательством их общей точки. Локальный `checkpoint #N` не является общим ID.
3. **Участники.** Сверьте roster, game build, моды и роли. Для неизвестных полей требуется ручное подтверждение и фиксация источника; иначе остановитесь.
4. **Файлы.** Для каждого участника нужен его собственный `coop_ckpt.sav`; HOST дополнительно требует свой `coop_ckpt_srv.sav`. ZIP проверяется по size/SHA-256; чужой файл не заменяйте.
5. **Локальный plan.** Используйте отдельный participant ZIP, импортируйте без перезаписи. Не переносите Steam credentials и полный профиль.
6. **Готовность.** Каждый участник вручную подтверждает готовность в новом лобби. Это не сетевое подтверждение менеджера.
7. **Marker.** Маркер не готовится, пока `ArchivePathResolver` не сопоставит virtual `@/profiles/<id>/save/coop_ckpt[_srv]/` с точным файлом выбранного профиля и ролью. Перед записью менеджер требует подтверждения, не перезаписывает имеющийся файл, не меняет TTL 15 минут. Одноразовый marker — не доказательство загрузки.
8. **Результат.** Запишите PASS, FAIL либо INCONCLUSIVE только по реальному игровому наблюдению и сохраните очищенные логи/параметры. Без запуска игры результат остаётся NOT_RUN.

V0.2 пока не реализует завершённый wizard, автоматический межкомпьютерный обмен или интерфейс подтверждения каждого peer. Существующая вкладка предоставляет базовые локальные операции и participant ZIP.
