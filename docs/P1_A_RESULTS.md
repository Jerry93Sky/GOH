# P1-A — результаты проверки готовности

Дата: 2026-11-23. Ветка: `codex/p1-a-runtime-validation`, основана на опубликованном P0.5.

## CONFIRMED_BY_CODE

- P0.5 manifest version 1 остаётся читаемым; координатор выпускает schema v2.
- Архивы до копирования и после проверяются по размеру, времени изменения, file ID и SHA-256; копия сравнивается с обоими состояниями источника. Нестабильные источники получают `SOURCE_UNSTABLE` и исключаются из плана. Отсутствующий источник даёт `INCOMPLETE`, неоднозначный — `SOURCE_AMBIGUOUS`, ошибка чтения/копирования — отдельный отчёт `CAPTURE_ERROR`.
- История TEST-A–F хранится отдельными append-only записями с уникальным `test_run_id`. Один checkpoint может иметь много попыток, включая FAIL и последующий PASS с новым run ID. Повтор identical request с тем же ID идемпотентен; конфликт ID не перезаписывает историю.
- План различает `latest_physically_available_checkpoint_id`, последний checkpoint с любым успешным игровым протоколом и последний TEST-B checkpoint. План истекает через 15 минут и становится `STALE_PLAN` при изменении выбранного manifest/архива/истории, истечении срока или появлении более новой совместимой точки.
- Исходники Coop Checkpoint v1.0.4 формируют локальные `%TEMP%\coop_checkpoint_reload_<role>.txt`, содержащие mission path, archive path и при наличии player ID base/count. Маркеры истекают через 15 минут. Scene loader проверяет их при обычной загрузке сцены, сравнивает mission path, строит load paths штатным path builder и удаляет маркер.
- В исходниках есть коррекция scene quant clock, server master scheduler, player ID remap и `autoassign` подразделений. Это статические сведения, не наши игровые измерения.
