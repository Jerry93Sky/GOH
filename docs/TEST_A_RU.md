# TEST-A: контрольная точка в текущей сессии

Требуются два игровых компьютера, отдельная тестовая установка/профиль и одинаковые game build, моды и Coop Checkpoint 1.0.4. Издатель релиза заявляет тестирование 1.069.0; это не переносится автоматически на другие build.

1. Сначала согласуйте участников и начните ту же историческую coop-миссию.
2. Через штатный интерфейс Coop Checkpoint создайте checkpoint. Зафиксируйте точный внутренний mission path, game build, порядок игроков, mod fingerprint, игровой timer/quant и выбранные объекты/цели.
3. Дождитесь завершения записи клиентских архивов на всех клиентах и серверного архива на локальном server хоста. Не копируйте файлы, пока размер/mtime меняется.
4. Скопируйте `coop_ckpt.sav` каждого игрока и `coop_ckpt_srv.sav` только с host server в изолированные временные каталоги. Используйте coordinator capture, который не читает пароли и профили целиком.
5. Проверяйте фактическую загрузку штатной кнопкой Reload в исходной сессии. Запишите результат, журналы Coop Checkpoint и скриншоты/сравнимые игровые признаки.
6. Не записывайте `RESTORE_VERIFIED` на основе этого офлайн приложения или симулятора. Для подтверждения нужен протокол теста в реальной игре, все участники и evidence.

Результат: `PASS`, `FAIL` или `INCONCLUSIVE` с фактическим build и приложенными доказательствами. Пакетный формат проверяет файлы и метаданные, но не понимает бинарное содержимое сохранения.
