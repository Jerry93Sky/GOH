# Независимая архитектура (предложение)

P0 не содержит кода внедрения в игровой процесс. Проект разделяет сбор доказательств, протокол checkpoint и возможный игровой adapter, чтобы анализ файлов не требовал изменения игры.

## Компоненты

1. **Исследовательский harness** — read-only сбор сведений о версии/хешах игры, мод-листе, ролях участников и файловых архивах. В P0 есть только сравнение дерева файлов.
2. **Checkpoint manifest** — собственная схема метаданных: UUID, mission/map, game build, хеш набора модов, игроки/слоты, host/server role, quant clock, время, список файлов/хешей/размеров, успешная запись/подтверждение. Формат должен быть версионированным и не включать игровой код.
3. **Согласование группы** — общий checkpoint ID и barrier: сервер сообщает точку, все peers фиксируют состояние и дают ACK; manifest публикуется только при завершении требуемых участников. Исходники не подтверждают наличие такого общего ACK.
4. **Store** — сначала локальные пользовательские каталоги, без облачного сервиса. Отдельные каталоги по сессии и checkpoint ID. Сохранность и копирование проверяются до восстановления.
5. **Recovery coordinator** — пользовательский запуск новой сессии, проверка совместимости roster/build/mods, выбор доступных копий и блокировка загрузки при неполном checkpoint. Автоматически не меняет оригинальные game resources.
6. **Game adapter (позднее)** — только после подтверждения API/форматов и теста на копии установки. Перед любым hook требуется проверка версии бинарника, секций, уникальности всех сигнатур и прологов; mismatch — отказ без записи в память. Никакого автоматического `version.dll` install.

## Поток восстановления

```text
quant checkpoint intent
        -> peer-local capture + server capture
        -> ACK + manifest commit
        -> game/session exits or crashes
        -> new lobby validates roster/build/mods
        -> choose experimentally validated archive set
        -> load all required participants
        -> compare state and record outcome
```

Пока не установлено, нужен ли комплект локальных архивов или достаточно серверного. Это решает эксперимент, а не схема заранее.

## Границы

- P1 — проверка форматов/совместимости снимков и проектирование manifest/ACK на внешнем harness.
- P2+ — только после P1 и явного решения команды о live-game adapter.
- Live join в выполняющуюся миссию — отдельный исследовательский трек.
